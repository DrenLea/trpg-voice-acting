混音时间轴 · 第 3 幕
痛点

一场几小时的故事，只剩几万字没人读的聊天记录

读不下去

骰点、规则争论、场外闲聊和剧情缠在一起，团员自己都不愿从头翻。

做不起

想做成音频回顾，要人肉剪台词、找配音、配音乐，一集要花好几天。

不懂结构

现成的 AI 配音只管"把一段文字读出来"，不知道谁在说话、哪里换场、何时该有音乐。

流水线

六步，代码能做的绝不交给模型

01
解析

识别发言者与角色，续行归并；支持 txt / docx。

0 token
02
清洗

正则先删指令、骰娘文案、场外行，折叠骰点结果；LLM 只对剩余行输出「序号 原因码」。

极低
03
拆角色

KP 自动拆成旁白与各 NPC，每个角色一份性格、语气、声线。

一次调用
04
改写剧本

逐幕生成 【角色】台词 · [音效] · 「BGM」 格式；三类校验，失败带错误反馈自动重试。

按幕
05
配音与素材

edge-tts 14 个中文神经声线，按行缓存；Openverse（Freesound + Jamendo，CC 授权、无密钥）按剧本描述自动检索下载，署名自动记录。

免费
06
混音出片

BGM −18 dB 淡入淡出、幕间留白，导出分幕与全片 mp3。Web 工作台里每处 BGM/音效可换、可静音、可调音量。

本地
底线

玩家的故事，就是玩家的故事

不改

不增删剧情、不改人设、不添加原文没有的心理活动。提示词硬规则 + 输出校验双重把守。

克制

BGM 只在氛围切换处出现，音效每幕不超过 5 处。配乐是底噪，不是主角。

不克隆

不做真人声线克隆，只用公开可选的声线库。

实测

样本《金枝》第一部分

310→131原始行 → 有效剧情行
规则层删 178，LLM 层只删 1
8幕 · 自动切分
235 句台词
1+7旁白 + 角色
新 NPC 自动登记
35/35音效与 BGM 标注
全部由 Openverse 自动落地
34min成片时长
默认 claude-haiku-4-5

剧本生成实测 haiku 比 sonnet 更守格式：sonnet 两次把记录当成对话续写，haiku 一次通过并自带氛围标注。更便宜的模型恰好也是更合适的模型。

时机

三件事第一次同时成立

免费 TTS 够像人了

edge-tts 的神经声线已能撑起长篇叙事，不再是"机器朗读"。

小模型够用了

结构化清洗与改写不需要旗舰模型，成本不再是门槛。

CC 音频有了统一入口

Openverse 免密钥聚合 Freesound 与 Jamendo，素材可以按描述自动取。

给谁用

开发者干净的 Python 模块 + CLI + FastAPI；TTS、LLM、素材源都是可替换的适配点。
