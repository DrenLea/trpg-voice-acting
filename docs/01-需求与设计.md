# 01 需求与设计：跑团记录 → 广播剧

## 1. 目标

输入：文字跑团（COC/DND 等）的原始聊天记录（QQ/Discord/骰娘导出，txt/log）。
输出：可监修的广播剧剧本（Markdown）+ 成品音频（mp3/wav）。

硬约束：
- 不擅自删改剧情、不改人设、不添加原文没有的心理活动。
- KP 拆分为：旁白 / 守密人（KP 本人）/ 各 NPC，各自独立声线。
- 音效、背景音克制，"不喧宾夺主"，不是每个场景都要 BGM。
- 全流程尽量省 token（见 §6）。

## 2. 需求拆解 → 流水线

| 步骤 | 需求条目 | 处理方式 | 主要工具 |
|---|---|---|---|
| S0 解析 | — | 把原始 log 规整为 `[{ts, speaker, text}]` | 纯代码（正则） |
| S1 清洗 | 一 | 剔除闲聊/规则讨论/OOC/重复骰点，只留骰点结果 | 规则预筛 + LLM 二次判定 |
| S2 角色表 | 二 | 识别 KP/PC/NPC，标注性格、声线倾向，绑定 TTS voice id | LLM 一次 + 人工确认 |
| S3 剧本化 | 三、五 | 对话记录 → 小说式广播剧剧本（固定格式） | LLM 按场景分块 |
| S4 氛围标注 | 四、五 | 场景切换处标 BGM，关键动作处标音效 | LLM（并入 S3）+ 人工微调 |
| S5 合成 | 六 | 逐行 TTS → 叠加 SFX/BGM → 混音导出 | edge-tts / CosyVoice + ffmpeg |

每一步产物都落盘为文件，下一步只读文件，不重跑上游。

## 3. 剧本格式（S3/S4 输出，供人工监修）

```markdown
# 《模组名》广播剧剧本

## 大纲
一段 150 字以内的剧情总览；分幕列出：第 N 幕 · 标题 · 一句话。

## 角色与声线
| 角色 | 身份 | 性格关键词 | 声线倾向 | voice_id |
|---|---|---|---|---|
| 旁白 | KP | 冷静克制 | 中低男声/女声，语速平稳 | zh-CN-YunyangNeural |
| 林默 | PC(玩家A) | 谨慎、话少 | 低沉、少起伏 | zh-CN-YunxiNeural |
| 老板娘 | NPC(KP) | 市侩、热情 | 中年女声，略快 | zh-CN-XiaoyiNeural |

## 第 1 幕 · 雨夜旅店
「BGM: 雨声+远雷，低音量」
【旁白】雨已经下了整整一夜。林默推开旅店的门，铃铛发出一声脆响。
[门铃响]
【老板娘】哟，这么晚还有客人？
【林默】一间房，谢谢。
[骰子：侦查 成功] ← 仅当需要保留判定语义时用此格式，否则改写为旁白叙述
【旁白】他注意到柜台下露出半截染血的布条。
「BGM: 切换 → 无」
```

约定：
- `【角色】` 台词/叙述；`[音效]` 独立一行插在对应位置；`「BGM: …」` 只在切换时出现，`「BGM: 无」` 表示停止。
- 旁白只叙述记录里明确描述过的动作/环境；不得写"他心想…"除非原文有。
- 幕的划分以场景（地点/时间）切换为准。

## 4. 角色表 JSON（S2 产物，`characters.json`）

```json
{
  "narrator": {"voice": "zh-CN-YunyangNeural", "rate": "-5%"},
  "roles": [
    {"name": "林默", "aliases": ["林", "默哥"], "type": "PC", "player": "玩家A",
     "traits": "谨慎话少", "voice": "zh-CN-YunxiNeural", "pitch": "-3Hz"}
  ]
}
```

aliases 用于 S3 归属台词，避免混淆。

## 5. 可复用产品调研（离线整理，上线后请核实版本/协议）

### 5.1 现成的"文本→多角色有声剧"整体方案
| 产品 | 类型 | 可复用点 | 缺口 |
|---|---|---|---|
| ElevenLabs Studio（原 Projects） | 商业 SaaS | 多角色分配声线、内置 Sound Effects 生成、直接导出 | 付费；中文声线一般；不做跑团清洗 |
| ebook2audiobook（GitHub 开源） | 开源 | 多引擎 TTS、按角色换声线、章节合成 | 面向 epub，无 SFX/BGM，无清洗 |
| 剪映/CapCut 文本朗读 | 桌面软件 | 中文声线多、时间轴混音直观 | 手动，无法批量自动化 |

结论：**没有直接覆盖"跑团清洗 + 剧本化"的现成品**；S0–S4 需自研（主要是 prompt + 少量代码），S5 完全复用现成库。

### 5.2 TTS（S5 核心，按优先级）
1. **edge-tts**（Python，免费，无需 key）—— 微软神经声线，中文声线约 10+（Xiaoxiao/Yunxi/Yunjian/Yunyang/Xiaoyi/Yunxia/辽宁/陕西方言等），支持 rate/pitch/volume。**默认方案**。
2. **CosyVoice 2**（阿里，开源，本地 GPU）—— 支持指令控制情绪、音色克隆，中文自然度高。用于对情绪要求高的角色。
3. **Fish Speech / GPT-SoVITS**（开源）—— 音色克隆，可让玩家用自己声音。
4. 商业 API 兜底：MiniMax speech、火山引擎豆包、Azure Speech（与 edge-tts 同源，付费版更稳）。

### 5.3 音效 / 背景音
- **优先用本地素材库**：freesound.org（CC）、Pixabay Sound Effects（免费商用）。建一个 `assets/sfx/` + `assets/bgm/` 目录，用文件名/tags.json 匹配 `[音效]` 关键词。零 token、零生成成本、可控。
- 生成式兜底：ElevenLabs Sound Effects API（商业）、Stable Audio Open / AudioLDM2（开源，质量不稳）。仅在素材库找不到时用。

### 5.4 混音
- **pydub + ffmpeg**：拼接、叠加、淡入淡出、音量包络，足够。无需 DAW。

### 5.5 LLM
- Claude（claude-sonnet-5 做 S1/S3，claude-haiku-4-5 做 S1 的规则二次判定）。
- 长记录用 prompt caching 缓存角色表与格式规范前缀。

## 6. 省 token 原则（对人和 agent 同样生效）

1. **代码能做的不用 LLM**：解析、去骰娘指令、去 `()`/`（）`/`//` 场外标记、合并同一人连续发言，全部正则。
2. **LLM 只看它需要的**：S1 按 200 行分块；S3 按幕分块，只附带角色表 + 格式规范 + 本幕清洗后文本。
3. **产物落盘、增量重跑**：修改某一幕只重跑该幕，不重生成整本。
4. **严格输出 schema**：LLM 输出即最终文件格式，不再二次整理。
5. **prompt 前缀固定**（角色表、格式规范）以命中缓存。
6. **人工监修在文本层完成**，音频只合成一次；改台词后只重合成受影响行（按行 hash 缓存 wav）。
7. agent 不得把整份 log 读进上下文；不得为"确认一下"重复读取已产出文件；不得自造 TTS/混音轮子。
