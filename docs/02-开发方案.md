# 02 开发方案

## 1. 技术选型

- 语言：Python 3.11+（TTS/音频生态最全）
- LLM：Anthropic SDK，`claude-sonnet-5`（清洗/剧本化）、`claude-haiku-4-5`（轻量判定）
- TTS：`edge-tts`（默认）；`cosyvoice` 可选适配器
- 音频：`pydub` + `ffmpeg`
- 无 Web UI；CLI + Markdown 监修，够用且最省成本

## 2. 目录结构

```
trpg-voice/
  assets/sfx/         音效素材（文件名即关键词，如 门铃.wav / 雷声.wav）
  assets/bgm/         背景音素材
  assets/tags.json    关键词 → 文件 映射（含别名）
  prompts/            clean.md / characters.md / script.md（固定前缀，命中缓存）
  src/trpgv/
    parse.py          S0 原始 log → lines.jsonl
    clean.py          S1 规则预筛 + LLM 分块判定 → clean.jsonl
    characters.py     S2 生成 characters.json
    script.py         S3/S4 按幕生成 script.md
    tts.py            S5a 逐行 TTS，按 hash 缓存到 cache/wav/
    mix.py            S5b 解析 script.md → 时间轴 → 混音导出
    cli.py            trpgv parse|clean|chars|script|tts|mix|all
  work/<模组名>/      每次运行的中间产物
  docs/
```

## 3. 各模块要点

### 语音库 `voices.py`（已实现）
- `trpgv voices` 在线拉取 edge-tts 全部中文声线（当前 14 个：zh-CN 7 + 方言 2 + zh-TW 3 + zh-HK 3）写入 `assets/voices.json`，含性别/人格标签/适用类别。
- S2 生成角色表时把该清单作为可选池给 LLM，人工可在 characters.json 里改 voice/rate/pitch。
- 不做声线克隆。

### S0 `parse.py`（已实现）
- 已验证格式：`<[昵称]角色>:内容`（骰娘昵称含"骰子"），续行无头部归上一发言者。
- 输出 `{"i":序号,"player":昵称,"role":角色,"text":内容}`。
- 纯代码，0 token。

### S1 `clean.py`（规则层已实现）
规则层（先跑，免费）：
- 删：`.` 开头指令行；骰娘非结果文案（开场白、暗骰、彩蛋文案）。
- 折叠：`技能: D100=a/b 结果` → `[骰子: 技能 结果]`，`1d3=1` → `[骰子: 1d3=1]`，归属到掷骰者角色。
- 删：以 `(` `（` `//` `场外` 开头的子行；整条为空则删。
- 合并同一 (player, role) 连续行；骰子行不合并。
- 样本实测：310 行 → 132 行（删 86、并 92）。
LLM 层（分块 ≤200 行）：
- 输入：角色表（若已有）+ 块文本；输出每行 `keep|drop` 及 drop 原因码（chat/rule/plot_discuss/dup_roll/ooc）。
- 只输出序号与标签，不回传原文，节省输出 token。

### S2 `characters.py`
- 从 clean.jsonl 采样每个 speaker 前 N 句 → 一次 LLM 调用产出 characters.json。
- KP 自动拆出 `narrator` + 检测到的 NPC；人工审阅后再进入 S3。
- 提供 `edge-tts --list-voices` 结果筛出的中文声线清单供选择。

### S3/S4 `script.py`
- 先让 LLM 按场景切换给出幕划分（只输出行号区间）。
- 逐幕生成：输入 = 固定前缀（格式规范 + 角色表）+ 本幕清洗文本；输出 = 该幕 Markdown。
- 提示词硬规则：不增删情节、不加心理活动、旁白只写记录中出现的描述；BGM 仅在氛围明显变化处标注；音效每幕 ≤5 处。
- 每幕独立文件 `work/x/scenes/01.md`，`script.md` 由拼接生成；改一幕只重跑一幕。

### S5a `tts.py`
- 逐行解析 `【角色】台词` → 查 characters.json 取 voice/rate/pitch → edge-tts 合成。
- 缓存键 = sha1(voice+rate+pitch+文本)，改台词只重合成变化行。
- 并发 8 路，失败重试 3 次。

### S5b `mix.py`
- 顺序拼接台词 wav，句间留 0.4s，幕间 1.5s。
- `[音效]` → 在 tags.json 查文件，叠加在该位置（找不到则记录到 `missing_sfx.txt`，不阻断）。
- `「BGM: x」` → 从该处开始循环叠加，-18dB，2s 淡入；`「BGM: 无」`或下一次切换时 2s 淡出。
- 导出 mp3 + 分幕 mp3。

### Web `web.py` + `static/index.html`（已实现）
- FastAPI + 单文件原生 HTML/JS，无前端构建。步骤通过 `subprocess` 调用 `python -m trpgv.cli`，日志写 `work/<x>/log.txt`，前端 1.5s 轮询。
- 项目 = `work/<名>/`，导入的原文保存为 `source.txt|docx`（parse 已支持直读 docx）。
- 声线试听 `/api/preview` 复用 tts 缓存键；剧本按幕保存后自动 `assemble` 重拼 script.md；素材上传写入 `assets/<kind>/` 并更新 `tags.json`。

### 素材获取 `assets.py`（已实现）
- 用 **Openverse API**（`api.openverse.org/v1/audio/`，无需密钥，CC 授权）：音效 `source=freesound`，BGM `category=music`（Jamendo）。返回 `url` 可直接下载 mp3。
- 中文描述 → 英文检索词：先查内置词典（~80 词，0 token）；未命中的描述一次 haiku 批量翻译。多词无结果时逐步去词回退。
- `trpgv assets -w work/x` 或工作台「一键自动补齐」按 `missing_assets.txt` 逐项下载到 `assets/<kind>/`，自动写 `tags.json` 关键词和 `assets/ATTRIBUTION.txt`（CC BY 需署名）。
- 实测样本 35 项两轮全部命中；自动选首个结果，质量需人工在工作台试听、必要时用搜索面板换。
- 调研过的替代：Mubert/TopMediai 等 AI 生成 API 免费额度仅限个人、需注册；Freesound 官方 API 需申请 token；Openverse 聚合两者且免密钥，故选它。

| 阶段 | 交付 | 验收 |

| M1 | parse + clean 规则层 + voices | ✅ 样本 310→132 行；14 个中文声线入库 |

## 4.1 实测结论
- **剧本生成用 haiku 而非 sonnet**：同一幕对比，sonnet 两次把记录当成对话续写/偷懒不改写，haiku 一次通过且自带 BGM/SFX 标注。默认 haiku，`--smart` 可切 sonnet。
- 输入给 LLM 的记录不能用 `【KP】` 标签（与输出格式同形导致照抄），改为 `KP: ` / `玩家[角色]: ` 前缀。
- 校验规则（缺旁白 / 含 KP·舞台说明·骰点字样 / 未知标签）+ 带错误反馈重试最多 3 次，实测 1 次内通过。
- Python 3.13 需 `audioop-lts`；ffmpeg 用 `imageio-ffmpeg` 自带二进制，无需系统安装；pydub 的 ffprobe 探测已打补丁跳过。

## 5. 风险与对策

- 台词归属混淆（玩家代 NPC 说话、KP 代 PC 描述）→ S2 aliases + S3 提示词要求"不确定归属时保留原 speaker 并加 `?` 标记"，交人工。
- edge-tts 情绪单一 → 角色表加 `style` 字段，后续可切 CosyVoice 适配器，接口不变。
- 素材库缺音效 → missing_sfx.txt 汇总后一次性补素材，不在流水线里生成。
- 长记录成本 → 分块 + 前缀缓存 + 只输出标签/序号；预估 10 万字记录 S1+S3 总消耗约 30–40 万 token。
